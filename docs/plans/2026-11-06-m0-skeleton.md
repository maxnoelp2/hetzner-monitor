## Goal

A runnable, CI-checked Rust skeleton: one binary that starts, applies migrations, and answers
health checks, runnable via Docker Compose. No Hetzner access, no domain logic yet.

## Acceptance criteria

- [x] `docker compose -f deploy/docker-compose.yml up --build` starts Postgres and the app; the app container becomes `healthy`.
- [x] `curl -fsS localhost:8080/healthz` → `200 {"status":"ok"}`.
- [x] `curl -fsS localhost:8080/readyz` → `200` while Postgres is up; `503` after `docker compose stop postgres`.
- [x] On startup the migration `0001_init` is applied; tables `organizations`, `users`, `memberships` exist.
- [x] `cargo fmt --all --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --all` pass locally **and** in GitHub Actions on the PR.
- [x] `cargo tree -i openssl-sys` finds nothing (rustls only).
- [x] Docs updated: `CLAUDE.md` (Commands, status), `ARCHITECTURE.md` (crate names), `docs/design/configuration.md`, `docs/roadmap.md` (M0 ticked).

## Approach

0. [x] **Toolchain** — install Rust via rustup (needs the owner's OK). Add `rust-toolchain.toml` pinning the
       current stable (verify the version at implementation time; edition 2024 needs ≥ 1.85) with `rustfmt` and `clippy`.
1. [x] **Workspace** — root `Cargo.toml` (`resolver = "3"`, edition 2024, shared `[workspace.dependencies]`,
       `[workspace.lints]` with `unsafe_code = "forbid"` and clippy `pedantic` as warn). Four crates:

       | Dir | Package | Kind | M0 content |
       |---|---|---|---|
       | `crates/hcloud` | `hm-hcloud` | lib | empty, crate docs stating the GET-only rule |
       | `crates/core` | `hm-core` | lib | empty, crate docs |
       | `crates/notify` | `hm-notify` | lib | empty, crate docs |
       | `crates/server` | `hm-server` | bin `hetzner-monitor` | config, DB pool, migrations, HTTP |

       **Deviation from ARCHITECTURE.md:** packages get an `hm-` prefix — a package named `core` would
       shadow Rust's built-in `core` crate. Directory names stay as documented. Update the code map.
2. [x] **Config** (`hm-server`) — load from env: `HM_DATABASE_URL` (required), `HM_BIND` (default `0.0.0.0:8080`),
       `HM_LOG` (default `info`), `HM_MODE` (`all|api|worker`, default `all`; in M0 only parsed and logged).
       Fail fast with a clear error on missing/invalid values. Unit-tested.
       `HM_MASTER_KEY` is **not** required yet — it becomes mandatory in M1 together with the encryption code.
3. [x] **Database** — `sqlx` (postgres, runtime-tokio, tls-rustls, migrate; **no compile-time `query!` macros yet**,
       so builds need no database). Migrations embedded with `sqlx::migrate!()` and run on startup.
       `migrations/0001_init.sql`: `citext` extension, `organizations`, `users`, `memberships`
       with `CHECK` constraints on `role`, UUID defaults via `gen_random_uuid()`, `timestamptz` columns.
4. [x] **HTTP** — Axum router: `GET /healthz` (liveness, no DB), `GET /readyz` (`SELECT 1` with 2 s timeout →
       200 / 503). `tower-http` trace layer, graceful shutdown on SIGINT/SIGTERM. Structured JSON logs via
       `tracing-subscriber` (`HM_LOG` filter).
5. [x] **Healthcheck subcommand** — `hetzner-monitor healthcheck` calls `/healthz` on `HM_BIND` and exits 0/1,
       so the distroless image needs no curl for Docker's `HEALTHCHECK`.
6. [x] **Tests** — unit tests for config parsing; integration tests with `#[sqlx::test]` (fresh DB per test,
       migrations applied) for `/healthz`, `/readyz` and the presence of the three tables.
7. [x] **Dockerfile** — multi-stage: `rust:<pinned>-slim` builder (dependency layer cached) →
       `gcr.io/distroless/cc-debian12:nonroot` runtime. `EXPOSE 8080`, `HEALTHCHECK` via step 5.
8. [x] **Compose** — `deploy/docker-compose.yml`: `postgres` (current major, verify at implementation;
       named volume; `pg_isready` healthcheck) + `app` (`depends_on: condition: service_healthy`).
       `deploy/.env.example` with all `HM_*` variables and placeholder values only.
9. [x] **CI** — `.github/workflows/ci.yml` on `pull_request` and `push` to `main`: jobs `fmt`, `clippy`,
       `test` (Postgres service container), `docker` (build only, no push). Toolchain from
       `rust-toolchain.toml`, cargo cache. `.github/dependabot.yml` for `cargo`, `github-actions`, `docker` (weekly).
10. [x] **Docs** — update `CLAUDE.md` (status → M0 done, real commands incl. how to start Postgres for tests),
        `ARCHITECTURE.md` (package names), `docs/design/configuration.md` (mark which vars exist), roadmap ticks,
        this plan's progress log.
11. [x] **Verify** — run every acceptance criterion by hand (compose up, curl, stop Postgres, `cargo tree`),
        record results in the progress log, open the PR.

## Dependencies (new crates — justification)

| Crate | Why |
|---|---|
| `tokio` | async runtime (ADR-0002) |
| `axum`, `tower-http` | HTTP API + trace layer (ADR-0002) |
| `sqlx` | Postgres pool + migrations, rustls (ADR-0003) |
| `serde`, `serde_json` | JSON responses, later config/API types |
| `tracing`, `tracing-subscriber` | structured logs (CLAUDE.md convention) |
| `anyhow` | error handling in the binary only |
| `thiserror` | typed config errors |
| ~~`reqwest`~~ | **dropped in M0** — the `healthcheck` subcommand uses a plain `tokio` TCP request instead; `reqwest` arrives with `hm-hcloud` in M1 |
| `http-body-util`, `tower` (dev only) | read response bodies / `oneshot` in integration tests |

Exact versions are taken from crates.io at implementation time.

## Out of scope

- Any Hetzner API code, encryption, auth, tenancy repositories, scheduler (M1+).
- Publishing images to GHCR, releases, `cargo-deny`/license audit (M5).
- `query!` compile-time checked queries and `.sqlx` offline data (decide in M1).
- Web frontend.

## Risks / open questions

- **Rust install needs your OK** (rustup from `https://rustup.rs`, installs into `~/.rustup` and `~/.cargo`).
  Alternative: build only inside Docker — slower feedback and agents can't run `cargo` directly. Recommendation: install rustup.
- `clippy::pedantic` as warnings + `-D warnings` in CI may be noisy; allow-list individual lints in `[workspace.lints]` if so.
- Distroless `cc` image needs glibc-compatible linking — fine with the Debian-based builder; switching to musl/`scratch` is not worth it in M0.
